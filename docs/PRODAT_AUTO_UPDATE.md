> Подготовленный run.sh использует только отдельные реквизиты PRODAT.

## Подтверждённое ограничение 04.11.2026

С действующим FTP-логином дерево `service.russvet.ru:21021` содержит только
`/pricat/` и `/pricat/TVER/`. В них находятся файлы PRICAT, файлов PRODAT нет.
Нельзя подтвердить каталог PRODAT, количество частей, идентификатор поколения,
даты и полноту набора. Два исторических файла от 20.09.2026 не доказывают контракт
новой выдачи. В общей БД 148872 товара; последняя PRODAT-реализация v1.3.0.

Эта версия устанавливает **ежедневную проверку доступности**, а не публикацию.
Отсутствие PRODAT и появление непроверенного набора не меняют каталог.
Автоматическое обновление номенклатуры остаётся заблокированным источником.

## Реализация и эксплуатация

`scripts/prodat-update/check.cjs` обходит только фактически найденные каталоги,
с ограничениями глубины, числа записей, времени и памяти. Символические ссылки
и предел глубины дают DISCOVERY_INCOMPLETE вместо утверждения об отсутствии.
Обычный FTP разрешён только для ранее согласованного service.russvet.ru:21021.
Реквизиты читаются процессом из существующего приватного файла PRICAT, без копии.
При ошибках в журнал попадает безопасный код, без исходного сообщения транспорта.

Одноразовый контейнер работает без DB credential, Docker socket и опубликованных
портов; root filesystem read-only, UID1001, cap-drop ALL, ограничены CPU/RAM/pids.
Существующие контейнеры и расписание PRICAT не изменяются.

Серверный каталог: `/home/shopadmin/elektrikamarket-prodat/`.
План установки cron: `17 9 * * *` на VPS с UTC, то есть **ежедневно 13:17 Астрахань**.
Команда проверки состояния:

```bash
/home/shopadmin/elektrikamarket-prodat/run.sh status
```

Поля: lastCheck, status, prodat (найденные кандидаты), directories, lastDownload,
lastImport, createdRecords, updatedRecords, publicationEnabled. Последние три
счётчика в режиме discovery остаются 0/false; null означает отсутствие операции.
Журналы: `state/status.json`, `state/events.ndjson`, `scheduler.log`.
SOURCE_UNAVAILABLE — в доступном дереве нет PRODAT; SOURCE_CONTRACT_REQUIRED —
найдены кандидаты, но контракт частей не подтверждён. CHECK_FAILED — ошибка связи
или лимитов. Команда publish отсутствует и отклоняется.

Чтобы отключить только эту проверку, удалить блок `elektrikamarket PRODAT discovery`
из crontab shopadmin. Не удалять строку PRICAT, журналы, образы или тома БД.

## Перед реализацией и включением публикации

Нужен доступ поставщика к PRODAT и проверенный контракт полного поколения:
перечень/число частей, client/receiver, даты, завершение загрузки, допустимый возраст.
Затем скачать реальный набор; проверить стабильность SIZE/MDTM, SHA-256, ZIP CRC,
ограничение распаковки, XML/DocType/идентичность/даты, дубли, категории и ссылки.
Непроверенный или усечённый набор не импортировать. Ничего не удалять по отсутствию.

Использовать только importProdat из scripts/import/prodat-import.cjs. Он публикует
каталог, штрихкоды и ссылки атомарно, сохраняет slug, manual/locked и отсутствующие
товары. Новую торговую логику, миграции и самостоятельное обнуление не добавлять.
Необходимы проверка аномалий ДО COMMIT на той же транзакции, needs-review marker
на случай потерянного COMMIT и связь последнего успеха с SHA полного набора.
Одних порогов числа XML-строк недостаточно для доказательства полноты частей.

## Совместная работа с PRICAT

PRODAT держит advisory lock 1707312401, PRICAT — 1707312402. Разные ключи сами
по себе не исключают одновременные импорты! Перед публикацией обвязка PRODAT
должна также держать 1707312402 на живом выделенном соединении весь импорт.
На VPS дополнительно использовать тот же host flock
`/home/shopadmin/elektrikamarket-pricat/update.lock`, что PRICAT. В работающую
PRICAT-автоматизацию для этого не требуется вносить изменение. При потере
блокирующего соединения публикацию останавливать; ручной импорт тоже учитывать.

После появления новых товаров обычный sync PRICAT вернёт NO_REMOTE_CHANGE.
Простой вызов importPricat с теми же SHA тоже пропустит уже принятые файлы.
Безусловный reprocess всей пары вызывает полную замену складского снимка,
поэтому он НЕ включён в ежедневную проверку. Требуется отдельный ограниченный
этап по подтверждённой принятой паре и поколению PRODAT: сверить SHA кеша с active
snapshot, провести dry-run, сохранить MANUAL/locked и карантин, доказать отсутствие
изменений существующих цен/складов, однократно опубликовать новый ассортимент.
Кеш PRICAT и его post-publication состояние также должны оставаться согласованными.
Испытание текущего поведения выполняется только на восстановленной копии.

Репетиция с искусственными файлами проверяет механизм, но НЕ заменяет испытание
актуальных файлов поставщика. До него первую публикацию в общей БД не включать.
