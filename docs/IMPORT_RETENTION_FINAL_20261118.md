## Подготовленное минимальное исправление

1. PRICAT уже ограничивает принятый cache двумя версиями каждого источника.
   Новый модуль `diagnostic-retention.cjs` сохраняет подробные NDJSON двух
   последних завершённых запусков. Старые известные отчёты заменяются
   компактными JSON: SHA-256, байты, количество записей и распределение причин.
   Результаты запусков, FTP-метаданные и принятые исходники сохраняются.
2. Очередь очистки записывается до удаления. Повтор после сбоя безопасен.
   Неопределённый COMMIT, review-маркеры, неизвестные пути, ссылки, повреждённый
   отчёт или изменившийся файл останавливают очистку доказательств.
   Ошибка обслуживания не меняет результат импорта. Ветка FTP без изменений
   не создаёт запуск и не запускает обход старой истории.
3. Старая история не подхватывается автоматически: требуется утверждённый
   перечень директорий для однократного `adoptDiagnostics`.
4. PRODAT уже ограничивает новые управляемые принятые пары двумя версиями.
   Однако прежняя bootstrap-пара и текущая legacy-директория не имеют receipts.
   Подготовлен `adoptAcceptedPairs`: принимает ровно две проверенные пары,
   проверяет каждый SHA до изменения реестра, требует миграционный маркер
   и подтверждённую текущую публикацию. SQL-сверка с успешными полными импортами
   остаётся обязательной проверкой установщика; сам модуль БД не открывает.
5. Торговая логика, ETIM, ручные данные, цены, остатки, снимки, cron и расписание
   этими изменениями не меняются. Код пока только локальный, не развёрнут.

Короткие локальные проверки файловой системы: 20 сценариев, 18 прошли,
0 ошибок, 2 проверки symlink пропущены на Windows. Проверены границы путей,
