# Технический паспорт: состояние, противоречия и план

Дата 2026-10-29, исходный срез 2f20c29. [Статусы](ARCHITECTURE.md).
Ниже нет утверждённых сроков. Приоритеты будущих работ — предложение к согласованию.

## Реализовано

| Возможность | Доказательство |
|---|---|
| Streaming XML/ZIP, кодировки, полная дедупликация | prodat.cjs, prodat.test.cjs |
| Каталог/бренды/RsCatalog, стабильные slug, locks | prodat-import.cjs, normalize/slug и integration tests |
| EAN, фото/документы, unresolved analog/related | barcode/reference modules и тесты; HTTP-скачиваний нет |
| PRICAT1/2, три склада, точные цены, raw/audit | pricat-import/normalize/store.cjs, pricat.test.cjs |
| MANUAL → PRICAT2 → PRICAT1; защита цены | storefrontPricesSql и тесты приоритетов |
| Карантин UOM/ItemsPerUnit и восстановление | applyBatch/readAvailableStocks, conflict/confirmed tests |
| Read-only каталог/карточка, поиск/фильтры/пагинация | web/lib/data.ts, app, smoke/availability |
| Standalone Docker, Caddy, роль SELECT, тестовый контур | deploy/storefront, web/Dockerfile; завершённое развёртывание |

Развёртывание подтверждено предыдущим отчётом этой работы: HTTPS и два логина,
20 товаров/цен/остатков, 10 карантинных товаров, неизменный полный отпечаток БД.
При составлении паспорта эти тесты и SSH-проверки заново не запускались.

## Не реализовано или ограничено

- ProductFeature существует, но ETIM не импортируется и не выводится.
- Нет корзины, заказа, OrderItem, регистрации, кабинета, индивидуальных цен/скидок,
  платежей, доставки, резервов, админки и UI управления manual/locked.
- Нет FTP downloader, расписания ежедневных импортов, очереди worker и уведомлений.
- Нет нескольких поставщиков и SupplierProduct; supplierCode пока глобально уникален.
- Нет поиска EAN/ETIM, полнотекстового/морфологического поиска.
- Нет media cache/storage/proxy, массовой проверки доступности ссылок.
- Нет документированного CI workflow/GHCR pipeline, auto deploy/rollback/blue-green.
- Health endpoint не проверяет БД; нет отдельного мониторинга сертификатов/бэкапов.
- Точный подсчёт наличия дорог; сравнительный SQL тест защищает семантику, но не SLA.
- Отсутствие новой записи не удаляет/обнуляет старые данные. TTL остатков не реализован.
- Read-only роль не является полной database-connect allowlist из-за PUBLIC CONNECT.

Этот паспорт фиксирует расхождения, но не меняет старую спецификацию,
торговый код, Prisma или данные.

## Открытые вопросы

1. **Владелец:** подтвердить будущие шкалы скидок, индивидуальные наценки и порядок
   применения ограничений; не переносить примеры 2%/3% в код как договорённость.
2. **Владелец + разработчик:** срок допустимого устаревания цен/остатков, частота
   загрузки, поведение при отсутствии товара/поля/источника; без молчаливого обнуления.
3. **Владелец:** нужен ли destructive sync полного PRODAT вообще и как явно
   отличать полный/частичный набор; ручные данные и история должны сохраняться.
4. **Разработчик + владелец:** ETIM — нормализация непустых значений, identities,
   типы/единицы, locks и семантика пустого значения; модель уже есть, writer нужен.
5. **Разработчик:** нужна ли дополнительная межисточниковая проверка упаковки при
   одинаковом UOM и разных ItemsPerUnit; текущий код не следует произвольно расширять.
6. **Владелец + администратор:** строгая isolation роли на уровне pg_hba/PUBLIC
   CONNECT, политика доступа второго разработчика и ротации секретов.
7. **Владелец:** целевая ветка интеграции, reviewer, GitHub branch protections,
   разрешение push/PR, registry и release approvals.
8. **Администратор:** независимый firewall audit, мониторинг HTTPS/health, резервное
   копирование и проверяемый restore; сроки хранения и место для копий.
9. **Владелец:** когда разрешено обновление сохраняемой тестовой БД и как повторять
   smoke после смены эталонного набора.
10. **Команда:** метрики задержки/нагрузки для каталога «В наличии» и допустимые
    методы оптимизации без изменения результатов карантина/цены.

## Предлагаемая последовательность

| Этап | Работа | Критерий готовности |
|---|---|---|
| P0: договорённости | Устранить версионную неоднозначность спецификации, согласовать процесс GitHub/права | Однозначный актуальный контракт, reviewer и порядок релиза |
| P1: эксплуатация | CI immutable images, безопасные release credentials, мониторинг/backup/restore drill, firewall audit | Воспроизводимый релиз и откат без затрагивания PG; проверяемое восстановление отдельной копии |
| P2: скорость/качество витрины | Замеры запросов, safe optimization, медиа/UX, устойчивые тестовые fixtures | Сохранена SQL-эквивалентность; измерено время; текущие торговые проверки проходят |
| P3: данные | ETIM, операционный UI диагностики/locks, согласованный scheduler | Нет потери ручных данных; идемпотентность, аудит, recovery и карантин покрыты тестами |
| P4: торговля | Модели клиентов/заказов, snapshot цены, количества/Multiplicity, checkout | Утверждены правила и безопасность; отдельный schema/design review |
| P5: расширение | Дополнительные поставщики, поиск/медиа/доставка | SupplierProduct спроектирован до подключения второго поставщика |

Приоритеты не являются разрешением менять текущую БД или начинать миграции.
