# Две принятые версии: узкое внедрение 19.11.2026

Разрешение: https://github.com/stron111-web/elektrikamarket/issues/4#issuecomment-7011828091.

PRICAT сохраняет две успешные полные версии каждого источника через существующий
FTP versions cache. После подтверждённого завершения сохраняет подробные NDJSON
только двух последних терминальных запусков. Старые отчёты и временные ZIP/XML
своих зарегистрированных запусков заменяет компактной сводкой (SHA, размеры,
число записей, распределение ошибок). Малые JSON, FTP-метаданные и два принятых
исходника не удаляются. Ошибочная или неопределённая публикация не удаляет
действующие успешные источники; review-маркеры запрещают обслуживание.

PRODAT использует существующий acceptedCandidates с лимитом две полные пары.
Для legacy текущей пары 15.11 и bootstrap 01.11 требуется точная сверка SHA
с успешными полными импортами 18 и 13. ETIM-only импорт 16 не является отдельной
версией полного каталога. Проверенный bootstrap переносится без копирования
в candidates, обе пары получают ownership receipts и запись в реестре.
Устаревшие bootstrap-настройки снимаются согласованно с сохранением rollback.
При следующей третьей принятой паре существующий GC удалит только старую
управляемую пару. Неизвестные исторические каталоги автоматически не подхватываются.

Установка: проверить отсутствие активного импорта; кратко захватить существующие
PRODAT check.lock и общий PRICAT update.lock; сохранить только затронутые код/
конфигурации и малые реестры. Построить два малых overlay образа на pinned
действующих image ID, сверить неизменность остального кода. Выполнить только
короткие filesystem-тесты без БД/FTP. Под locks сверить read-only БД/исходники,
провести однократную явную регистрацию известных исторических директорий,
переключить только pinned runtime image ID. Cron и watchdog сохраняются.
Не запускать publish/check для проверки. Наблюдать следующий штатный запуск.

Откат: прежние образы сохранены; восстановить image pin и затронутый код.
Не перематывать принятые состояния к старым версиям и не восстанавливать в рабочую
БД дамп ради исправления ротации. Bootstrap-конфигурацию можно вернуть только
вместе с обратным перемещением прежней пары при доказанном наличии её файлов;
после последующей штатной ротации старый bootstrap не требуется.

Перед удалением единственной контрольной PostgreSQL требуется актуальный
pg_dump после последней публикации. При отсутствии создаётся ровно один дамп
с экспортированным согласованным read-only snapshot. Пригодность проверяется
успехом pg_dump, SHA-256, TOC всех public tables и полным декодированием всех
архивных секций pg_restore в /dev/null. Это проверка архива, а не новое пробное
восстановление; предыдущая проверка восстановления и старые дампы сохраняются.
Новые БД/volumes не создаются. Удалять только точный контрольный том и проверенные
тестовые контейнеры после проверки отсутствия подключений и текущих rollback-ссылок.
