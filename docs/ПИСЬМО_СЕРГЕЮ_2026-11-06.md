## Что мешало, и что из этого нельзя повторить

Ключ Яндекса в файлы Git не записывали и в закрытый Compose на сервере не клали. Он живёт только в секрете сборки превью `PREVIEW_YANDEX_JS_API_KEY`. Сборка превью вписывает его в страницу до `next build`. Если ключ до страницы не дошёл, сборка превью останавливается и чужую карту не подставляет.

Три вещи, без которых карта снова не откроется:

1. Ключ должен попасть в саму страницу при сборке именно того сайта, где карту хотят видеть. Мало передать его в окружение контейнера: страница собирается раньше и пустое значение затирало ключ. На превью это делает `web/scripts/write-yandex-public-key.cjs` из секрета сборки. В Git остаётся пустая заготовка `web/lib/yandex-public-key.ts`.
2. Запрос скрипта карты должен уносить имя сайта. Это уже стоит в загрузчике: перед адресом скрипта `referrerPolicy = strict-origin`. Без имени сайта Яндекс отвечает 403, рамка пустая, а в консоли красной строки нет. Общую политику сайта из-за этого не меняли.
3. В кабинете Яндекса, ключ JavaScript API, в ограничении по HTTP Referer должен быть точный адрес того сайта, и панель нужно сохранить. Для превью там уже есть `preview.elektro-24.ru`. Этой записи достаточно только для превью. Для боевого адреса магазина его нужно добавить рядом и нажать «Сохранить». Новый ключ создавать не нужно.

Пока ключа на странице нет, кнопка «Выбрать на карте» оставляет пустую рамку и пишет, что карта на этом запуске не подключена. Если ключ есть, а Яндекс отказал, надпись другая: «Яндекс Карта не открылась».

## Если переносить возможность на другой сайт

Код загрузчика уже в этой ветке. Для другого адреса отдельно нужны свой секрет сборки, та же запись ключа в страницу до сборки и разрешённый адрес в кабинете Яндекса. Закрытый Compose превью для карты не используется.
