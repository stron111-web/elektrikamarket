# Андроник: локальная среда регистрации, корзины и заказов

Рабочая ветка — существующая `preview/friend`. Новую ветку для этой подготовки
не создавали. Проверенный исходный HEAD — eaff840. Ваши компоненты/страницы не менялись.

## Быстрый запуск на Windows, Linux или macOS

Нужны Node.js 24, Docker Desktop/Engine с Compose v2 и checkout `preview/friend`.
Не переключайте ветку с несохранённой работой и не используйте reset/clean.
Полученный от владельца `andronik_dev_environment.zip` распаковать **в корень
checkout**, предварительно проверив содержимое. Он добавляет только deploy/dev и
четыре новых документа; веб-код не заменяет. На Windows:

```powershell
Expand-Archive -LiteralPath .\andronik_dev_environment.zip -DestinationPath .
node deploy/dev/dev.cjs setup
node deploy/dev/dev.cjs check
npm --prefix web ci --ignore-scripts
node deploy/dev/dev.cjs web
```

Распаковку выполнять без `-Force`: существующие файлы молча не заменять.
Архив не содержит паролей: каждый компьютер генерирует собственные локальные
реквизиты при setup. Последняя команда запускает сайт на 127.0.0.1:3000 и передаёт
два URL **через окружение дочернего процесса**, без вывода значений:

- `DATABASE_URL` — локальный каталог, роль `storefront_preview_ro`, read-only;
- `SHOP_DATABASE_URL` — отдельная локальная БД покупателей, роль
  `storefront_preview_shop_app`, будущий CRUD без DDL.

Серверный клиент покупателей должен быть отдельным от клиента каталога.
Он пока не реализован этим набором: его делает Андроник. Не заменять DATABASE_URL.
Prisma понимает `schema=shop`; при использовании postgres.js удалить параметр
`schema` из URL перед созданием клиента, сохранив серверный search_path=shop.
Не использовать NEXT_PUBLIC_* для подключений и не отправлять URL в браузер.

PostgreSQL 17 доступен только локально: 127.0.0.1:55432. При конфликте порта до
первого setup установить LOCAL_PG_PORT в своей оболочке и использовать его же
во всех последующих командах. Входящего доступа из LAN/интернета нет.
Compose-проект `elektrikamarket-local-dev` не использует сети/тома VPS.

## Таблицы и миграции покупателей

БД `elektrikamarket_preview_shop`, пустая схема `shop`. Таблиц покупателей,
организаций, корзин или заказов здесь не создавали. Миграционная роль
`storefront_preview_shop_migrator` владеет только схемой shop. Приложение не владеет
таблицами и не имеет CREATE/TEMP/административных привилегий.

1. Подготовить отдельные миграции для SHOP, не применять существующий Prisma-каталог
   как схему покупателей. SQL должен создавать объекты в `shop`, не в `public`.
2. Проверить подготовленный SQL только локально:

```text
node deploy/dev/dev.cjs migrate путь/к/согласованной_миграции.sql
node deploy/dev/dev.cjs grant имя_проверенной_таблицы другая_проверенная_таблица
node deploy/dev/dev.cjs check
```

Скрипт выбирает фиксированный локальный Compose-контейнер, не читает .env,
передаёт SQL в stdin, использует миграционную роль и транзакцию. Он не может быть
направлен на VPS параметром URL. При ошибке останавливается без очистки/ремонта.
Миграции, несовместимые с транзакцией, требуют отдельной локальной проверки.

Выдача прав — только явному списку проверенных таблиц и их последовательностям.
Служебные underscore-таблицы, включая _prisma_migrations, не выдаются приложению.
Права по умолчанию не открывают все будущие таблицы. До grant приложение не сможет
писать в новую таблицу — это ожидаемое ограничение, а не неисправность подключения.

Для Prisma потребуется собственная конфигурация схемы SHOP, которую определит
Андроник. Набор проверяет SQL; migrate dev с автоматически создаваемой shadow DB
здесь не настроен. Не повышать VPS-роли до CREATEDB ради shadow DB.

PostgreSQL не поддерживает внешний ключ из базы покупателей к другой базе
каталога. Сохраняйте реальные productId/supplierCode как ссылки приложения и
проверяйте их отдельным серверным чтением каталога. Состав таблиц/полей этот
документ не задаёт. Покупателей/заказы в товарную базу не добавлять.

## Проверки и остановка

```text
node deploy/dev/verify-local.cjs
node deploy/dev/verify-catalog.cjs
node --test deploy/dev/secret-loader.test.cjs
node deploy/dev/dev.cjs stop
```

`verify-local` рассчитан на пустую БД **до ваших миграций**: создаёт синтетические
probe-таблицы внутри откатываемой транзакции и требует 0 таблиц после неё. После
ваших миграций используйте dev.cjs check и собственные тесты; не удаляйте таблицы
ради прохождения проверки пустой fixture. verify-catalog требует установленного
web/node_modules/postgres и использует существующие функции reader проекта.

`stop` сохраняет локальный том. Повторный setup после успешного выполнения только
проверяет существующую среду, не восстанавливает данные заново. Сброса/удаления БД
скрипт не предоставляет. После частичного неуспеха не удалять том вслепую.

Все `.local/*` исключены из Git: там локальные URL, пароль локального администратора,
метка готовности и компактный каталог. Не коммитить каталог с секретами, не выводить
URL через echo/Compose config; использовать `config --quiet`. На Windows хранить
checkout в личном профиле с закрытым ACL, не в общем сетевом каталоге.

Перенос миграций на VPS — только после отдельного обзора и разрешения владельца.
Push в preview/friend автоматически разворачивает код, **не должен запускать
миграции**. Не добавлять их в startup, Dockerfile, Actions или API.
