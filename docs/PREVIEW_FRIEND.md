# Другу: интерфейс магазина в Cursor

Preview пока подготовлен, но не включён. Эти инструкции применяются после того,
как владелец создаст `preview/friend` и активирует автопубликацию.

1. Клонируй `stron111-web/elektrikamarket`, открой папку в Cursor и прочитай
   `AGENTS.md` и `docs/BUSINESS_RULES.md`.
2. Перейди в свою ветку (первый раз):

   ```sh
   git fetch origin
   git switch --track origin/preview/friend
   ```

   Если локальная ветка уже есть — `git switch preview/friend`. Работай в этой
   ветке, не в main. Не делай force push.
3. Установи Node.js 24. Подготовь зависимости и проверь сборку:

   ```sh
   npm --prefix web ci --ignore-scripts --no-audit --no-fund
   npm --prefix web run typecheck
   npm --prefix web run build
   npm --prefix web run dev
   ```

   Открывай локальный адрес из терминала, обычно http://127.0.0.1:3000/catalog.
   Для каталога нужна **собственная локальная тестовая БД** с read-only доступом;
   владелец отдельно поможет её подготовить. Сборка сама не создаёт БД и не запускает
   миграции. Basic Auth логин developer — только для сайта, не пароль PostgreSQL.
   Не подключай локальные эксперименты к сохраняемой VPS базе и не открывай 5432.
4. Меняй внешний вид: компоненты, стили, расположение блоков и адаптивность.
   Не меняй самостоятельно `scripts/import`, Prisma, цены/остатки/упаковки/карантин,
   серверный reader, Docker, workflow и `deploy/`. Для таких изменений сначала
   согласуй отдельную задачу с владельцем. Не запускай migrations/import/reset.
5. Проверь страницы локально, desktop/mobile, поиск, карточки, отсутствие ошибок
   сборки. Затем отправь только нужные UI-файлы:

   ```sh
   git status --short
   git diff --check
   git add web/ПУТЬ_К_ИЗМЕНЁННОМУ_ФАЙЛУ
   git commit -m "ui: краткое описание изменения"
   git push origin preview/friend
   ```

   В коммит не должны попадать `.env`, ключи, пароли, дампы или файлы поставщика.
6. Открой GitHub → Actions → **Preview storefront**. Дождись зелёного результата.
   При красном статусе прочитай ошибку сборки/проверки, исправь UI и сделай новый push.
   При серверной/DB/HTTPS ошибке сообщи владельцу; не обходи проверки и не «ремонтируй»
   сервер. Не отключай авторизацию и noindex.
7. Результат появится на https://preview.elektro-24.ru/catalog. Владелец входит как
   owner, друг — developer, с существующими паролями test-сайта. Браузер может снова
   попросить их для другого домена. Пароль получи у владельца защищённым способом,
   не через GitHub issue/commit. Доступ SSH, Docker и пароли БД для просмотра не нужны.

Push в эту ветку обновляет только preview. Он не меняет main и test.elektro-24.ru.
Принятый интерфейс затем переносится в main отдельным Pull Request и review владельца.
Технические подробности, границы изоляции и откат: [PREVIEW_DEPLOYMENT.md](PREVIEW_DEPLOYMENT.md).
