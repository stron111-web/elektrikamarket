# Компактный локальный каталог для корзины

Экспортирован непосредственно из действующего коммерческого снимка VPS 01.11.2026
через REPEATABLE READ READ ONLY транзакцию, statement_timeout=15s. PRICAT не читался,
импорт или rebuild не запускались. Исходный active snapshot=1, 125082 позиции.

Набор: **120 реальных товаров и предложений**, 382 бренда и 244 категории с
исходными идентификаторами/родителями. Размер JSON — 290463 байта. SHA-256:

```text
4b1ab1a8698f19e43eb062557d87f0825ec263a4882ca2f4d464173b0256c567
```

Состав: реальные Product.id, supplierCode, slug, названия, артикулы, описание,
brandId/categoryId, публичные розничные цены и stocks активного снимка, UOM,
ItemsPerUnit/ItemsPerUOM/Multiplicity. Выборка охватывает комбинации единицы продажи,
источника цены и числа доступных складов — до 8 товаров каждой комбинации.

Исключены: закупочные и клиентские цены, исходные PRICAT/PRODAT, rawData,
журналы/ошибки импортов, служебные URI, секреты, учётные записи покупателей,
данные организаций/корзин/заказов. Фотографии и документы не переносились: таблицы
пустые, интерфейс использует штатное отсутствие изображений. Это набор для логики
ссылок корзины/цен/остатков, а не полный визуальный каталог.

Данные лежат в `deploy/dev/.local/catalog-sample.json`, рядом SHA-256. Они включены
в отдельный передаваемый ZIP, но исключены из Git вместе с `.local`. Генерируемые
локальные пароли/URL в ZIP не включены. Набор — снимок на дату экспорта и не получает
автоматических обновлений; подключение домашнего ПК к PostgreSQL VPS не нужно.

## Восстановление

`node deploy/dev/dev.cjs setup` создаёт только собственный локальный Docker-проект,
проверяет SHA, отказывается перезаписывать существующие целевые БД, применяет
существующую схему **каталога** из пяти SQL-файлов репозитория в новую локальную БД
и загружает whitelist полей. БД покупателей остаётся пустой.

Product/brand/category ID и значения публичных цен/остатков сохраняются.
Маленькие синтетические import_runs/import_files служат только FK-подложкой
метаданных локального снимка и явно помечены sanitized-local-fixture: это не
перенесённые служебные журналы и не доказательство локального успешного импорта.
purchasePrice остаётся NULL; catalog_ro не имеет SELECT этого столбца.

Полный каталог **не нужен** для текущего reader и разработки корзины: проверены
каталог, поиск, фильтры бренда/категории, пагинация, чтение товара, реальные ID,
точное совпадение цен/складов sample с reader. Карточки товаров вне этих 120 IDs
локально отсутствуют; не ожидать совпадения общего количества с VPS. Внешние ключи
из БД покупателей в другую БД каталога невозможны: связи проверяет приложение.

Для нагрузочных измерений на 125082 позициях/полного покрытия всех категорий нужна
отдельная более широкая обезличенная копия. Передавать весь прежний database.dump
вместо этого набора нельзя: он содержит внутренние коммерческие данные и аудит.
