# PRICAT v2: план развёртывания для отдельного согласования

Этот документ не разрешает публикацию или изменение VPS. Текущая задача — испытания только существующей изолированной копии. Рабочие cron остаются в режиме check с периодами PRICAT 3 часа и PRODAT 12 часов.

## 1. Завершить и зафиксировать проверку

Сохранить фактический отчёт реальных пар, исчезновения/возврата, карантина, UOM/упаковок, ручных и защищённых данных, повторного запуска и отката. Разделить реальные исходники и контрольные изменения XML. Зафиксировать проверенный код и SHA; raw XML, дампы, коммерческие отчёты и конфигурации с секретами в Git не добавлять.

## 2. Подготовить production-кандидат без установки

- Подключить `reviewed-import.cjs` к существующему `update.cjs` через явную версию политики. Установленный старый запускатель сейчас этот модуль не использует.
- Включить новые модули в существующий Dockerfile; проверить собранный immutable image на той же изолированной копии. Overlay-тест кода на прежнем runtime-образе сам по себе не проверяет содержимое нового release image.
- Заменить прежние процентные veto сверкой источников/кодов и техническими/торговыми инвариантами. Снижение числа строк и количества предложений не должно становиться самостоятельным запретом. Конфликт/ошибка идентифицируемого кода — карантин только его источника; неизвестная идентичность, повреждение и неправильный источник — отказ опасного действия.
- Сохранить единственные существующие host/DB-блокировки, защиту MANUAL/locked, ценовые приоритеты, точную арифметику, карантин и атомарное построение снимка. Новых пересчётчиков цен/остатков не создавать.
- Сохранить metadata-skip FTP и last-success-state, если они уже установлены соответствующей веткой: неизменённые исходники не скачивать. Не объявлять наличие подготовки в Git доказательством работы этого механизма на VPS. Ошибка не продвигает принятую версию. Явный reprocess последней принятой пары остаётся доступен без новых FTP-файлов.
- Разделять версии источников: новый PRICAT1 может использовать последнюю принятую неизменённую PRICAT2 и наоборот; источник не подменять другим складом или случайным файлом. Согласованность проверять по фактическим идентификаторам, привязке поставщика/клиента и метаданным получения, без новых произвольных порогов.
- Добавить production-контроль прогресса/таймауты и диагностику с сохранением журналов до удаления временного контейнера. Предусмотреть явное штатное завершение по SIGTERM и откат открытой транзакции; не полагаться на стандартную обработку сигналов Node в роли PID1 контейнера. Тестовый watchdog не установлен в рабочую автоматику. Причину исторического зависания нельзя считать доказанной только по успешному обходу ZIP-потока.

После этой подготовки повторно испытать именно release-кандидат. Затем представить diff, образ, конфигурацию и конкретный порядок запуска владельцу. Не менять main и витрины.

## 3. Перед разрешённой рабочей публикацией

Отдельное разрешение владельца обязательно. До него никаких production publish/deploy и переключений cron.

1. Сверить актуальное состояние и источники, текущие образы, cron, lock и свободное место. Числа исторической тестовой пары не выдавать за прогноз для другой актуальной пары.
2. Создать свежий pg_dump и проверить восстановление без новой лишней большой копии, используя согласованную существующую изолированную среду. Сначала сохранить результаты испытаний; не выполнять восстановление поверх рабочей БД.
3. Сохранить прежние образ и конфигурацию для отката только импортёра. PostgreSQL, Test, Preview и Caddy не перезапускать.
4. Под существующей общей блокировкой выполнить один контролируемый запуск проверенного кандидата; проверить фактические таблицы, карантин, снимок и доступность витрины. Повтор вслепую запрещён.

## 4. После контролируемого запуска

При ошибке публикации последний корректный снимок должен сохраниться. Принятые версии FTP не продвигать; сохранить диагностику. Откат кода/конфигурации не означает разрешение восстанавливать дамп поверх рабочей БД. Такую операцию отдельно согласовывать.

Автоматический publish включать только по отдельному разрешению после проверки рабочего запуска. Использовать прежнее единственное задание, сохранить согласованные периоды и отсутствие пересечения записи PRODAT/PRICAT. Не создавать параллельный планировщик.
