# Одна общая тестовая среда

Код Андроника остаётся в preview/friend. Каталог читается прежней ролью и прежним
DATABASE_URL_FILE. Покупатели, сохранённые корзины и заказы находятся только в
существующей elektrikamarket_preview_shop, схема shop. Новых постоянных баз нет.

## Вход и проверка прав

Для preview предусмотрен вход в /admin через существующие owner/developer,
проверяемые Caddy Basic Auth на всём сайте. Новых паролей сотрудников нет.
Режим включается только серверной конфигурацией PREVIEW_STAFF_BASIC_AUTH=1
и только при STOREFRONT_DATABASE_ROLE=storefront_preview_ro. Отдельный
PREVIEW_STAFF_MAP сопоставляет эти два имени с техническими email сотрудников.
currentStaff каждый раз проверяет наличие сотрудника в shop.staff; отсутствие
записи лишает прав админки. Покупательская сессия не даёт прав сотрудника.

Это доверие к существующему reverse proxy: порт приложения не должен публиковаться,
Caddy обязан проверять Basic Auth до всех запросов. Приложение использует именно
Authorization, а не подделываемые X-User/X-Preview-Staff. Не включать этот режим
на публичном прямом Node-порту или без авторизации прокси. Caddyfile не меняется.
Кнопка выхода из старой staff-cookie сессии не сбрасывает браузерный Basic Auth;
для раздельных проверок используйте отдельные профили/приватные окна браузера.
Без флага сохраняется прежний механизм staff sessions, используемый локально.

## Первая установка владельцем

Четыре SQL из deploy/dev/migrations применяются одной транзакцией только
к пустой shop-схеме существующей shop-БД и от миграционной роли. DDL Андроника
сохраняется. **Готовые локальные хеши паролей из 004 не переносятся:** вместо них
создаются две staff-записи с отключённым парольным входом. App получает CRUD
только бизнес-таблиц, SELECT staff/staff_sessions, необходимые sequence USAGE,
не получает CREATE, TRUNCATE, миграционный URL или права записи в каталог.

Миграции выполняются отдельно от старта, Actions и deployer. Повторная начальная
установка при существующих таблицах запрещена. Перед ней сохраняется backup.
Проверенные SQL/хеши и журнал применения сохраняются в защищённом каталоге VPS.

enable-shared-shop.py — однократная операция root с резервной копией Compose:
добавляет только app-secret, preload и opt-in staff mapping в preview. Существующий
каталоговый URL, Caddy, test-web, PostgreSQL и задания PRICAT не меняются.
Исходные secret-файлы 0600 shopadmin сохраняются; отдельная runtime-копия
0400 UID1000 создаётся в закрытом root-каталоге. Миграционный секрет туда не входит.
В Compose остаётся ${PREVIEW_IMAGE}, поэтому будущий обычный push продолжает
обновлять код без потери общего подключения. Пересоздаётся только preview;
возможен краткий перерыв. При ошибке проверки возвращается прежний Compose/web,
покупатели и заказы не удаляются. Ручной rollback: тот же root-скрипт --rollback.

## Проверка двумя разработчиками

1. Андроник входит на preview под developer, регистрирует **вымышленного** покупателя,
   добавляет разрешённый товар в корзину и оформляет пробный заказ.
2. Владелец под owner открывает /admin/clients и /admin/orders: видны те же записи.
3. После обновления контейнера записи остаются в PostgreSQL. Локальные БД на ПК
   для общего тестирования не нужны. Не вводить реальные персональные данные.

Платёжный экран текущего кода — тестовый, внешнего банка/уведомлений нет.
Регистрация покупателя сохраняет собственную покупательскую учётную запись;
это не дополнительный пароль сотрудника или сайта.

## Что пока не переносится

- SQL buyer_markup_price не применяется: он меняет общую товарную БД и требует
  отдельного согласования. Пока тестируйте обычных покупателей и скидку от розницы;
  статус «наценка» зависит от этой ещё не установленной функции.
- Перенос локальных записей Андроника необязателен. Сначала согласуйте список
  именно тестовых данных. Экспортировать только buyers (без password_hash),
  individual_profiles, organizations, cart_items, orders, order_items; не переносить
  staff, sessions, staff_sessions, payments, token_hash/guest_key и секреты.
  Импортировать в транзакции с сопоставлением buyer_id/order_id, проверкой реальных
  product_id/supplier_code и без перезаписи совпавших записей. Старые пароли не
  переносить: импортированные анкеты оставлять без парольного входа до отдельного
  согласованного способа активации. Готового универсального импортёра таких записей
  здесь нет; весь локальный dump поверх общей БД восстанавливать нельзя.
- Push обновляет код. Новые изменения схемы после этих четырёх миграций сначала
  проверяются локально и отдельно согласуются; startup не должен мигрировать БД.
