## Очистка собственных временных файлов

Новая версия отмечает только созданные ею каталоги `.prodat-owned.json`.
Удаление разрешено исключительно внутри такого каталога: два указанных ZIP,
их незавершённые `.part` и собственная квитанция. Перед первым unlink проверяются
все дочерние объекты; неизвестный файл, hardlink или symlink блокирует очистку.
Рекурсивного удаления по вычисленному пути нет.

- При UNCHANGED_BYTES новая повторная копия удаляется после сохранения состояния,
  прежняя проверенная пара остаётся. Новый timestamp затем даёт metadata-skip.
- Не завершившиеся загрузки удаляются, не продвигая успешные метаданные.
- Сохраняются текущий кандидат, две последние подтверждённые опубликованные
  пары и предыдущая проверенная пара, если текущий кандидат отклонён.
- Очистка после publish разрешена только после подтверждённого результата всей
  существующей цепочки PRODAT + scoped PRICAT. Учтён COMMIT перед сбоем записи
  bookkeeping: последняя подтверждённая пара регистрируется до следующей очистки.
- needs-review запрещает очистку. Старые каталоги без квитанций, исследовательские
  ZIP, bootstrap и второй пакет очистки не удаляются вообще.

Это ограничивает накопление **будущих собственных** временных файлов. Это не
очистка уже существующей истории VPS. ETIM, принятые исходники и БД не удаляются.
Новые процентные ограничения не добавлялись, прежние PRODAT-политики не менялись.

## Точный план после отдельного разрешения

1. Проверить здоровье сервисов, свободное место, отсутствие needs-review,
   текущие две части `/allstock/TVER/`, принятый PRICAT и активный снимок.
   При отличии файлов от проверенного кандидата сначала проверить новый полный
   набор; не смешивать части и не использовать прогноз другого поколения.
2. Создать свежий согласованный pg_dump рабочей БД, сохранить предыдущие backup.
   Проверить архив и восстановление в уже существующей изолированной среде,
   без новой БД/volume и без повторения полноразмерной матрицы испытаний.
   Если резервная копия непригодна — остановиться до изменения флага.
3. Сохранить актуальные config/runtime.env/cron для отката. Под блокировкой
   PRODAT атомарно изменить только publicationEnabled на true. Cron пока check.
4. **Один раз** выполнить существующий launcher:

   ```sh
   /home/shopadmin/elektrikamarket-prodat/run.sh publish
   ```

   Сам launcher берёт check.lock и общий PRICAT update.lock; дополнительный
   внешний flock вокруг этой команды не нужен. PRICAT cron остаётся включён.
   При занятости общего lock публикации не пересекаются. Не удалять lock и
   не останавливать PRICAT, чтобы принудительно запустить PRODAT.
5. Дождаться подтверждения PRODAT и существующего scoped-согласования новых
   товаров с последней принятой парой PRICAT (reprocess=true). Не вводить второй
   пересчёт цен/остатков. Сверить created/updated/ETIM, manual/locked, существующие
   торговые строки и предложения, атомарность нового снимка, FTP SHA и маркеры.
   Если новых товаров нет, дополнительный коммерческий снимок может не понадобиться.
6. Проверить очистку только собственных временных кандидатов и сохранность
   принятых пар. Повторную публикацию ради проверки не запускать.
7. Только после успеха заменить ровно одну cron-строку PRODAT с check на publish,
   сохранив `0 11,23 * * *` (03:00/15:00 Самары). PRICAT/watchdog не менять.
   Проверить оба сайта и локальные журналы; дать фактические числа.

При ошибке — остановка, PRODAT остаётся/возвращается в check с выключенным
флагом. Код/образ можно вернуть из маленькой резервной копии только PRODAT.
При неопределённом COMMIT сохранить маркеры и диагностику; защитное блокирование
общей цепочки не обходить. Не повторять publish вслепую и не восстанавливать
дамп поверх рабочей PostgreSQL без отдельного согласования.
